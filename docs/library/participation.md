# Ways to Participate

Not everyone wants to build a new product in a weekend. Offering more than one way to take part brings in more people, and it gives open source projects real contributors.

**AfroHacks**, the first hackathon at the **AfroTech Conference**, had two ways to participate:

1. **Build a project** with proprietary and open source technologies and AI.
2. **Contribute to open source,** such as Linux Foundation and IBM open source projects.

## Path 1: Build a project

The standard path. Teams build a working prototype for a challenge or track, then submit and present it. Everything in [Win](../participate/index.md) and [Challenges](../challenges/index.md) applies.

## Path 2: Contribute to open source

Participants make real contributions to existing open source projects: code, documentation, tests, translations, design, or bug reports.

**Why it works**

- People who don't want to start from scratch still ship something real.
- Contributions last after the weekend, and many become the start of ongoing involvement.
- Open source foundations and companies get new contributors, and participants get a public record of their work.

**How to set it up**

1. **Pick three to five projects** with active maintainers who agree to take part.
2. **Ask each project for a list of starter issues,** labeled "good first issue" or similar, before the event.
3. **Bring a maintainer or mentor** from each project, in person or online, to review and unblock.
4. **Run a short setup session** on forking, branching, pull requests, and each project's contribution guide.
5. **Define what counts:** an opened pull request, a merged pull request, documentation, or a filed and reproduced bug.

**How to judge it**

| Criterion | What judges look for |
|---|---|
| Impact | How much the contribution helps the project and its users |
| Quality | Follows the project's guidelines; tests and docs included |
| Collaboration | Worked with maintainers and responded to review |
| Growth | What the contributor learned, and whether they'll keep contributing |

Running a whole event around open source? See [Run an open source hackathon](../open-source/index.md). For other kinds of tracks, see [Track options](tracks.md).

## Offering both

- Let people choose at registration, and allow switching on the day.
- Keep both paths in the same room so builders and contributors meet.
- Give each path its own prizes, and celebrate both at the awards.
- Put the open source projects in the [starter kit](starter-kits.md) next to the build resources.
