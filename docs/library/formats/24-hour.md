# 24 Hours (2 Days)

A 24-hour hackathon over two days, with hacking overnight. This was the format for the A2Tech360 Local Impact track and Hack Dearborn, and it is the most common shape for university and community hackathons.

## Sample schedule

**Day 1**

| Time | Block | Notes |
|---|---|---|
| 8:00 AM | Check-in, registration, and breakfast | Have provisioning links ready at the door |
| 9:00 AM | Welcome with the challenge sponsors | Sponsors introduce themselves and present their own challenges |
| 9:30 AM | Hackathon briefing | Rules, tracks, prizes, judging, and how to submit |
| 9:45 AM | AI tools and provisioning workshop | Team registration and where to find the tools. Everyone leaves with accounts and credits working |
| 10:30 AM | **Design for AI** workshop (open to all) | Teams start from the user and the challenge, not the model |
| 11:30 AM | Team formation and track selection | |
| **12:00 PM** | **Hacking begins** | All code must be written after this |
| 12:30 PM | Lunch | |
| 1:30 PM | Sponsor workshops (open to all) | Hands-on with sponsor tools while teams build. Centralized, or in parallel rooms |
| 3:00 PM | [How to Win a Hackathon](../../participate/index.md) | Teams have an idea by now; this sharpens it and plans the pitch |
| 4:00 PM | Office hours | Sponsors and mentors walk the room |
| 7:00 PM | Dinner and networking | |
| 8:00 PM | Evening build block | |
| 12:00 AM | Overnight building | |

**Day 2**

| Time | Block | Notes |
|---|---|---|
| **9:00 AM** | **Draft submission checkpoint** | A draft is required to be judged; teams can keep editing |
| 10:00 AM | Brunch and final office hours | |
| 10:30 AM | Code freeze, then final build and demo prep | |
| **12:00 PM** | **Final submissions due** | Hard deadline |
| 12:30 PM | Judging | 5-minute presentations, in parallel rooms if needed |
| 2:00 PM | Closing and awards | |

## What's different about 24 hours

- **Run Design for AI before hacking begins,** so teams form around a user and a problem. See the [Design for AI](../../participate/resources.md#design-pitch-and-developer) resources.
- **Add a draft checkpoint.** A morning draft deadline means every team has something submitted before the final push, and judges can start reading early.
- **Set up first, then build.** Provisioning and Design for AI run before hacking begins, so every team starts with working accounts and a real user in mind.
- **Sponsor workshops can run centralized or in parallel.** Weekend events usually have rooms to spare. Run tool workshops for everyone, and track workshops in their own rooms.
- **Set up a Discord** (or similar) with announcements, help channels, and a channel per track.
- **Plan judging capacity.** With many teams, you need more judges (20 or so for a large event) and parallel rooms.
- **How to Win works best mid-afternoon on day one,** after teams have formed and have an idea.
