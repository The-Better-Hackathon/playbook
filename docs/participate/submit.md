# Submit and Demo

## Build plan checkpoints

Work backwards from the deadline and write real times next to each one.

- [ ] Idea locked (roles assigned, repo set up)
- [ ] MVP working end to end
- [ ] Feature freeze: stop adding, start polishing
- [ ] Demo video recorded
- [ ] Submitted

## Tech and data rules

- [ ] Use only data you're allowed to use, and note the source and license
- [ ] No personal information in your data or demo
- [ ] No API keys in your repo (use environment variables or a `.env` file in `.gitignore`)
- [ ] Note which AI tools you used, and for what

Check the event's own rules too, for example whether code written before the event is allowed.

## 60-second demo video

| Time | Beat | What you show and say |
|---|---|---|
| 0:00–0:10 | User | Who this is for |
| 0:10–0:20 | Problem | What gets in their way |
| 0:20–0:50 | Three clicks through the solution | Click 1, click 2, click 3 |
| 0:50–1:00 | Impact | What changes for them |

Record it before the final morning so a flaky live demo can't sink you. One screen recording with a voiceover is enough.

## Submission checklist

- [ ] Repo URL (public, with a README)
- [ ] Demo video URL
- [ ] Problem and solution statements
- [ ] Technologies used, including AI tools
- [ ] Submitted before the deadline

## When things go wrong

Only your team knows "that wasn't supposed to happen." Keep screenshots and the recorded demo on hand. If it breaks on stage, keep pitching and talk through what should happen. People love humility and tenacity.
