# Host and Judge

A sample one-day open source hackathon. Adjust the times to your [format](../run/formats/index.md).

| Time | What happens |
|---|---|
| 9:00 AM | Check-in and breakfast |
| 9:30 AM | Welcome: the three paths, the projects, the rules, and the Code of Conduct |
| 10:00 AM | Maintainers introduce their projects and challenges (two minutes each) |
| 10:30 AM | Setup session, then build and contribute |
| 12:30 PM | Lunch |
| 1:30 PM | Maintainer review windows: pull requests get reviewed while people are still in the room |
| 4:30 PM | Final pull requests and submissions |
| 5:00 PM | Demos and a contribution showcase |
| 6:00 PM | Awards for every path |

## How to judge

| Path | What judges look for |
|---|---|
| Build | A working prototype, clear use of open source, a proper license, and a useful README |
| Contribute | Impact on the project, quality, following the project's process, and responsiveness to review |
| Models and data | Rigor, reproducibility, and clear documentation |

Give extra credit for **merged** work, but don't penalize pull requests still in review at the end of the day. Review often takes longer than a hackathon.
