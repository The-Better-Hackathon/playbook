# Write Maintainer Challenges

Borrowed from Hack Michigan: turn what a project really needs into a short brief, with the solution left to the teams.

## Do this

1. **Ask each maintainer** what would help the project most: a missing feature, a documentation gap, accessibility, performance, onboarding, or an integration with another tool.
2. **Write it as a brief** using the [challenge brief template](../challenges/brief-template.md): the problem, what good looks like, the resources, and the criteria.
3. **Add a definition of done,** such as "merged into main" or "accepted by a maintainer," so teams know what to aim for.
4. **End with one test** a judge can apply, for example: *"Would a new contributor get from clone to first pull request in under an hour with these docs?"*
5. **Publish the challenges** with the rest of your event information, before registration closes.
